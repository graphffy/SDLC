## 1. Введение

Данный документ содержит спецификацию требований к программному продукту Repetitio — веб-системе для подготовки к экзаменам с использованием интервального повторения учебного материала. Документ определяет назначение продукта, его основные функции, ограничения и требования к качеству работы. Он предназначен для заказчика, разработчиков и специалистов, участвующих в тестировании и проверке системы.

### 1.1 Назначение документа

Настоящая спецификация требований к ПО (SRS) определяет функциональные и нефункциональные требования к системе Repetitio. Документ описывает, что должна обеспечивать система, не определяя конкретные способы реализации её компонентов.

Спецификация предназначена для заказчика, разработчиков и тестировщиков. Она используется в качестве основы для проектирования, разработки, проверки и приёмки программного продукта.

### 1.2 Область применения продукта

Repetitio — веб-система для организации самостоятельной подготовки пользователей к экзаменам. Продукт предоставляет возможность создавать экзамены и учебные темы, планировать повторение материала с использованием интервального алгоритма и фиксировать результаты подготовки.

Система позволяет отслеживать слабые темы, просматривать расписание повторений и оценивать общую готовность к экзамену. Основная цель продукта — помочь пользователю организовать подготовку и систематически повторять материал.

В область применения входят управление экзаменами и темами, планирование повторений, регистрация результатов и отображение статистики подготовки. Система не предназначена для проведения экзаменов, автоматической проверки ответов или предоставления образовательных материалов.

### 1.3 Определения, акронимы и сокращения

| Term | Definition |
|---|---|
| API | Application Programming Interface — набор определений и протоколов для создания и интеграции прикладного программного обеспечения |

## 2. Обзор продукта

### 2.1 Перспектива продукта

Repetitio является самостоятельным программным продуктом, предназначенным для организации индивидуальной подготовки к экзаменам. Система разрабатывается как веб-приложение и не является частью существующей образовательной платформы.

Пользователь взаимодействует с продуктом через веб-браузер. Основные данные системы включают учётные записи пользователей, экзамены, учебные темы, расписание повторений и результаты подготовки.

Система не зависит от внешних образовательных сервисов и не требует интеграции с университетскими информационными системами. Владельцем продукта в рамках разработки является заказчик проекта.

### 2.2 Функции продукта

Основные функции системы Repetitio:

1. Регистрация новых пользователей и авторизация существующих пользователей.
2. Создание, просмотр, редактирование и удаление экзаменов.
3. Создание и управление учебными темами, связанными с экзаменами.
4. Автоматическое планирование повторений учебных тем с использованием заданных временных интервалов.
5. Просмотр расписания запланированных и выполненных повторений.
6. Сохранение результатов подготовки по каждой учебной теме.
7. Определение слабых тем на основании сохранённых результатов.
8. Расчёт общего процента готовности пользователя к экзамену.
9. Отображение статистики подготовки и результатов повторений.

### 2.3 Ограничения продукта

Система должна соответствовать следующим ограничениям:

- Продукт должен предоставлять доступ к основным функциям через веб-браузер.
- Для использования системы пользователь должен иметь доступ к сети Интернет.
- Доступ к персональным данным и операциям пользователя должен предоставляться только после авторизации.
- Данные разных пользователей должны быть изолированы друг от друга.
- Система должна использовать интервалы повторения, предусмотренные функциональными требованиями.
- Система не должна автоматически генерировать учебные материалы или вопросы.
- Система не должна использовать модели искусственного интеллекта или машинного обучения для выполнения основных функций.
- Пользователь должен самостоятельно создавать экзамены и учебные темы, а также оценивать результаты своей подготовки.

### 2.4 Характеристики пользователей

Основным классом пользователей системы являются люди, самостоятельно готовящиеся к экзаменам.

**Обычный пользователь:**

- имеет базовые навыки работы с компьютером или мобильным устройством;
- умеет пользоваться веб-браузером;
- использует систему для организации личной подготовки;
- может создавать экзамены и учебные темы;
- просматривает расписание повторений и сохраняет результаты подготовки.

Специальная техническая подготовка для работы с системой не требуется. Административные функции управления пользователями в рамках текущей версии продукта не предусматриваются.

### 2.5 Допущения и зависимости

При разработке системы принимаются следующие допущения:

- Пользователь имеет устройство с установленным современным веб-браузером.
- У пользователя имеется стабильное подключение к сети Интернет.
- Пользователь самостоятельно вводит достоверную информацию об экзаменах и учебных темах.
- Пользователь самостоятельно оценивает качество усвоения учебного материала.
- Пользователь регулярно обращается к системе для выполнения запланированных повторений.
- Серверное окружение и база данных доступны для хранения и обработки пользовательской информации.

Работа системы зависит от доступности веб-сервера, базы данных и сетевого подключения пользователя. При недоступности этих компонентов пользователь не сможет полноценно выполнять операции с данными.

## 3. Требования

В данном разделе представлены функциональные и нефункциональные требования к системе Repetitio. Каждое требование имеет уникальный идентификатор, заголовок, описание, обоснование, критерии приёмки и метод проверки.

### 3.1 Внешние интерфейсы

Система должна предоставлять пользователю веб-интерфейс и взаимодействовать с программными компонентами, необходимыми для хранения и обработки данных. Специальные аппаратные интерфейсы для работы системы не требуются.

#### 3.1.1 Пользовательские интерфейсы

Пользовательский интерфейс системы должен обеспечивать доступ к основным функциям Repetitio.

Интерфейс должен содержать следующие основные страницы:

- страницу регистрации и авторизации;
- главную страницу с общей информацией о подготовке;
- страницу со списком экзаменов;
- страницу просмотра и редактирования экзамена;
- страницу управления учебными темами;
- страницу расписания повторений;
- страницу внесения результатов подготовки;
- страницу статистики и анализа результатов.

Навигация между основными разделами должна быть доступна из общего меню приложения.

Система должна отображать сообщения об успешном выполнении операций и возникновении ошибок. При отсутствии данных должны отображаться соответствующие информационные сообщения.

Пользовательский интерфейс должен адаптироваться к размерам экрана компьютера, планшета и мобильного устройства.

#### 3.1.2 Аппаратные интерфейсы

Система не требует специализированного аппаратного оборудования.

Для работы с продуктом пользователь должен иметь устройство, способное запускать современный веб-браузер и подключаться к сети Интернет.

Взаимодействие с аппаратными устройствами напрямую не осуществляется.

#### 3.1.3 Программные интерфейсы

Система должна взаимодействовать со следующими программными компонентами:

| Компонент | Назначение |
|---|---|
| Веб-браузер | Предоставление пользовательского интерфейса и взаимодействие с системой |
| Серверная часть приложения | Обработка пользовательских запросов и выполнение бизнес-логики |
| База данных | Хранение учётных записей, экзаменов, тем, расписания и результатов подготовки |

Обмен данными между пользовательским интерфейсом и серверной частью должен выполняться через программный интерфейс приложения.

Серверная часть должна обеспечивать проверку входных данных и корректную обработку ошибок при выполнении запросов.

### 3.2 Функциональные требования

#### REQ-FUNC-001 — Регистрация пользователя

**ID:** REQ-FUNC-001

**Title:** Регистрация пользователя

**Statement:** Система должна предоставлять возможность регистрации нового пользователя с использованием уникального адреса электронной почты и пароля.

**Rationale:** Регистрация необходима для создания индивидуальной учётной записи и хранения персональных данных подготовки пользователя.

**Acceptance Criteria:**
- Пользователь может открыть форму регистрации.
- Пользователь может указать адрес электронной почты и пароль.
- Система проверяет корректность введённых данных.
- Система не допускает регистрацию с уже используемым адресом электронной почты.
- При успешной регистрации создаётся новая учётная запись.
- При ошибке система отображает соответствующее сообщение.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-002 и REQ-SEC-001.

#### REQ-FUNC-002 — Авторизация пользователя

**ID:** REQ-FUNC-002

**Title:** Авторизация пользователя

**Statement:** Система должна предоставлять возможность входа в учётную запись с использованием зарегистрированного адреса электронной почты и пароля.

**Rationale:** Авторизация необходима для предоставления доступа к персональным данным пользователя и предотвращения несанкционированного доступа.

**Acceptance Criteria:**
- Пользователь может открыть форму авторизации.
- Пользователь может ввести адрес электронной почты и пароль.
- При вводе корректных данных система предоставляет доступ к учётной записи.
- При вводе некорректных данных система отклоняет авторизацию.
- После успешной авторизации пользователь получает доступ только к собственным данным.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-001 и REQ-SEC-001.

#### REQ-FUNC-003 — Управление экзаменами

**ID:** REQ-FUNC-003

**Title:** Управление экзаменами

**Statement:** Система должна предоставлять пользователю возможность создавать, просматривать, редактировать и удалять экзамены.

**Rationale:** Управление экзаменами необходимо для организации учебного материала по отдельным направлениям подготовки.

**Acceptance Criteria:**
- Пользователь может создать экзамен, указав его название и дату проведения.
- Пользователь может просматривать список созданных экзаменов.
- Пользователь может открывать информацию об отдельном экзамене.
- Пользователь может изменять название и дату проведения экзамена.
- Пользователь может удалить созданный экзамен после подтверждения операции.
- При удалении экзамена система должна удалять связанные с ним учебные темы, расписание повторений и историю результатов подготовки.
- Перед удалением система должна предупредить пользователя о том, что связанные данные также будут удалены.
- Система не допускает выполнение операций с экзаменами другого пользователя.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-004, REQ-FUNC-005 и REQ-FUNC-007.

#### REQ-FUNC-004 — Управление учебными темами

**ID:** REQ-FUNC-004

**Title:** Управление учебными темами

**Statement:** Система должна предоставлять пользователю возможность создавать, просматривать, редактировать и удалять учебные темы, связанные с определённым экзаменом.

**Rationale:** Разделение экзамена на отдельные темы позволяет организовать подготовку и отслеживать результаты по каждой части учебного материала.

**Acceptance Criteria:**
- Пользователь может создать тему внутри выбранного экзамена.
- Пользователь может указать название темы.
- Пользователь может просматривать список тем экзамена.
- Пользователь может изменять название существующей темы.
- Пользователь может удалять созданные темы.
- Система не допускает создание тем для экзаменов другого пользователя.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-003, REQ-FUNC-005 и REQ-FUNC-007.

#### REQ-FUNC-005 — Планирование повторений

**ID:** REQ-FUNC-005

**Title:** Планирование повторений

**Statement:** Система должна автоматически планировать повторение учебной темы после сохранения результата подготовки. Интервалы успешных повторений должны составлять 1, 3, 7, 14 и 30 дней. Если результат подготовки ниже 60%, система должна сбрасывать последовательность интервалов к начальному значению.

**Rationale:** Автоматическое планирование повторений позволяет организовать регулярное возвращение к изученному материалу и поддерживать процесс подготовки. Единый порог оценки обеспечивает согласованность правил планирования повторений и определения слабых тем.

**Acceptance Criteria:**
- После сохранения результата система определяет дату следующего повторения.
- Для последовательных успешных повторений используются интервалы 1, 3, 7, 14 и 30 дней.
- При результате ниже 60% последовательность интервалов сбрасывается к начальному значению — 1 день.
- При результате 60% и выше система переходит к следующему интервалу последовательности.
- После достижения максимального интервала в 30 дней он используется для последующих успешных повторений.
- Дата следующего повторения сохраняется в системе.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-006, REQ-FUNC-007 и REQ-FUNC-008.

#### REQ-FUNC-006 — Просмотр расписания повторений

**ID:** REQ-FUNC-006

**Title:** Просмотр расписания повторений

**Statement:** Система должна предоставлять пользователю возможность просматривать расписание повторений учебных тем, включая повторения, запланированные на текущий день, будущие даты и прошедшие даты, если они не были выполнены.

**Rationale:** Расписание позволяет пользователю контролировать план подготовки, своевременно выполнять повторения и отслеживать пропущенные задания.

**Acceptance Criteria:**
- Пользователь может открыть страницу расписания повторений.
- Система отображает повторения, запланированные на текущую дату.
- Система отображает повторения, запланированные на будущие даты.
- Если дата повторения прошла, а пользователь не выполнил его, система отображает такое повторение как просроченное.
- Просроченные повторения продолжают отображаться в расписании до момента выполнения.
- Система не изменяет дату просроченного повторения автоматически.
- После выполнения просроченного повторения система рассчитывает дату следующего повторения относительно фактической даты его выполнения.
- Для каждого повторения отображается название соответствующей учебной темы и его текущий статус.
- Пользователь может перейти к выбранной теме из расписания.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-005 и REQ-FUNC-007.

#### REQ-FUNC-007 — Сохранение результатов подготовки

**ID:** REQ-FUNC-007

**Title:** Сохранение результатов подготовки

**Statement:** Система должна предоставлять пользователю возможность сохранять и редактировать результаты подготовки по каждой учебной теме в виде числовой оценки от 0 до 100 процентов.

**Rationale:** Сохранение и редактирование результатов необходимо для отслеживания уровня усвоения материала, исправления ошибочно введённых оценок и расчёта показателей готовности к экзамену.

**Acceptance Criteria:**
- Пользователь может выбрать учебную тему и внести результат подготовки.
- Значение результата должно находиться в диапазоне от 0 до 100 процентов.
- Система сохраняет результат и связывает его с соответствующей темой.
- Пользователь может просматривать ранее сохранённые результаты подготовки.
- Пользователь может изменить ранее сохранённый результат.
- После изменения результата система обновляет сохранённое значение без создания дополнительной записи о повторении.
- После изменения результата система пересчитывает общий процент готовности к экзамену.
- После изменения результата система обновляет статус слабой темы.
- После изменения результата система пересчитывает дату следующего повторения с учётом исправленного результата.
- Система использует актуальные результаты подготовки при формировании статистики.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-005, REQ-FUNC-008, REQ-FUNC-009 и REQ-FUNC-010.

#### REQ-FUNC-008 — Определение слабых тем

**ID:** REQ-FUNC-008

**Title:** Определение слабых тем

**Statement:** Система должна определять слабые учебные темы на основании результатов подготовки. Тема должна считаться слабой, если последний сохранённый результат по ней ниже 60%.

**Rationale:** Определение слабых тем позволяет пользователю выявлять недостаточно усвоенные части материала и уделять им дополнительное внимание.

**Acceptance Criteria:**
- Система анализирует последние сохранённые результаты по учебным темам.
- Тема с результатом ниже 60% определяется как слабая.
- Темы с результатом 60% и выше не отображаются как слабые.
- Система отображает список слабых тем в соответствующем разделе.
- При изменении результата подготовки статус темы обновляется.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-007 и REQ-FUNC-009.

#### REQ-FUNC-009 — Расчёт готовности к экзамену

**ID:** REQ-FUNC-009

**Title:** Расчёт готовности к экзамену

**Statement:** Система должна рассчитывать общий процент готовности пользователя к экзамену на основании последних сохранённых результатов подготовки по учебным темам. Все темы должны иметь одинаковый вес при расчёте общего показателя. Если по теме отсутствует сохранённый результат, для неё должен использоваться показатель 0%.

**Rationale:** Показатель готовности позволяет пользователю оценить текущий уровень подготовки к экзамену. Использование одинакового веса тем обеспечивает единый и понятный способ расчёта без необходимости дополнительной оценки сложности или объёма учебного материала.

**Acceptance Criteria:**
- Система получает последние сохранённые результаты по темам выбранного экзамена.
- Если по теме отсутствует результат, система учитывает её с показателем 0%.
- Все темы имеют одинаковый вес при расчёте общего процента готовности.
- Общий процент готовности рассчитывается как среднее арифметическое результатов по всем темам экзамена.
- Рассчитанное значение отображается пользователю в процентах с точностью до двух знаков после запятой.
- При изменении результатов подготовки показатель готовности пересчитывается.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-007 и REQ-FUNC-008.

#### REQ-FUNC-010 — Статистика подготовки

**ID:** REQ-FUNC-010

**Title:** Просмотр статистики подготовки

**Statement:** Система должна предоставлять пользователю возможность просматривать статистику подготовки к экзаменам на основании сохранённых результатов и выполненных повторений.

**Rationale:** Статистика позволяет пользователю отслеживать ход подготовки и оценивать изменения результатов во времени.

**Acceptance Criteria:**
- Пользователь может открыть раздел статистики.
- Система отображает количество выполненных повторений.
- Система отображает результаты подготовки по учебным темам.
- Система отображает общий процент готовности к выбранному экзамену.
- Данные статистики соответствуют сохранённым результатам пользователя.
- Статистика обновляется после сохранения нового результата подготовки.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-007, REQ-FUNC-008 и REQ-FUNC-009.

### 3.3 Качество обслуживания

В данном подразделе определяются требования к производительности, безопасности, надёжности, доступности и наблюдаемости системы Repetitio.

#### 3.3.1 Производительность

**ID:** REQ-PERF-001

**Title:** Время отклика системы

**Statement:** Система должна обрабатывать стандартные пользовательские запросы и возвращать результат не более чем за 2 секунды. Загрузка главной страницы с информацией о подготовке не должна занимать более 3 секунд при нормальных условиях эксплуатации.

**Rationale:** Приемлемое время отклика необходимо для комфортного использования системы и выполнения основных операций без длительного ожидания.

**Acceptance Criteria:**
- Стандартные пользовательские запросы обрабатываются не более чем за 2 секунды.
- Главная страница с информацией о подготовке загружается не более чем за 3 секунды.
- Проверка выполняется при нормальной нагрузке на систему.
- Время отклика измеряется с момента отправки запроса до получения ответа.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-001–REQ-FUNC-010.

#### 3.3.2 Безопасность

**ID:** REQ-SEC-001

**Title:** Защита учётных записей пользователей

**Statement:** Система должна обеспечивать аутентификацию пользователей перед предоставлением доступа к персональным функциям приложения. Пароли пользователей не должны храниться в открытом виде.

**Rationale:** Защита учётных записей необходима для предотвращения несанкционированного доступа к персональным данным пользователей.

**Acceptance Criteria:**
- Для доступа к персональным функциям пользователь должен пройти авторизацию.
- Пароли не сохраняются в базе данных в открытом виде.
- При вводе неверных учётных данных система отклоняет авторизацию.
- Неавторизованный пользователь не может получить доступ к закрытым разделам приложения.

**Verification Method:** Test, Inspection

**More Information:** Связано с REQ-FUNC-001 и REQ-FUNC-002.

**ID:** REQ-SEC-002

**Title:** Разграничение доступа к пользовательским данным

**Statement:** Система должна обеспечивать доступ пользователя только к тем экзаменам, темам, результатам и другим данным, которые принадлежат его учётной записи.

**Rationale:** Разграничение доступа необходимо для сохранения конфиденциальности пользовательской информации.

**Acceptance Criteria:**
- Пользователь может просматривать только собственные экзамены.
- Пользователь может изменять и удалять только собственные данные.
- Попытка доступа к данным другого пользователя должна отклоняться.
- Проверка прав доступа выполняется для операций чтения и изменения данных.

**Verification Method:** Test

**More Information:** Связано с REQ-FUNC-001, REQ-FUNC-002 и REQ-SEC-001.

**ID:** REQ-SEC-003

**Title:** Защита передаваемых данных

**Statement:** Система должна обеспечивать защищённую передачу данных между пользовательским браузером и серверной частью приложения с использованием HTTPS.

**Rationale:** Защищённое соединение необходимо для предотвращения перехвата пользовательских данных при передаче по сети.

**Acceptance Criteria:**
- Обмен данными между браузером и сервером выполняется через HTTPS.
- Незащищённое HTTP-соединение не используется для передачи пользовательских учётных данных.
- При отсутствии защищённого соединения система не должна предоставлять возможность передачи пароля.

**Verification Method:** Test, Inspection

**More Information:** Связано с REQ-FUNC-001 и REQ-FUNC-002.

- Основные функции системы сопровождаются необходимой документацией.

**Verification Method:** Inspection

**More Information:** Связано с REQ-BUILD-001 и REQ-OBS-001.

#### 3.5.5 Повторное использование

**ID:** REQ-REUSE-001

**Title:** Повторное использование программных компонентов

**Statement:** При разработке системы допускается повторное использование общих программных компонентов для реализации однотипных операций и функций.

**Rationale:** Повторное использование компонентов позволяет сократить дублирование кода и упростить сопровождение системы.

**Acceptance Criteria:**
- Общие операции могут быть вынесены в отдельные программные компоненты.
- Повторяющаяся логика не должна без необходимости дублироваться.
- Используемые сторонние библиотеки должны быть совместимы с проектом.

**Verification Method:** Inspection

**More Information:** Связано с REQ-MAINT-001.

#### 3.5.6 Переносимость

**ID:** REQ-PORT-001

**Title:** Переносимость пользовательского приложения

**Statement:** Пользовательская часть системы должна обеспечивать работу в современных веб-браузерах независимо от операционной системы устройства пользователя.

**Rationale:** Переносимость необходима для использования системы на различных устройствах без разработки отдельных версий приложения для каждой операционной системы.

**Acceptance Criteria:**
- Система доступна через современные браузеры в операционных системах Windows и Linux.
- Пользовательский интерфейс корректно отображается в поддерживаемых браузерах.
- Для доступа к основным функциям не требуется установка отдельного настольного приложения.

**Verification Method:** Test

**More Information:** Связано с REQ-AVAIL-001.

#### 3.5.7 Стоимость

В рамках учебного проекта отдельный бюджет на разработку и эксплуатацию системы не устанавливается.

При разработке допускается использование бесплатных инструментов, библиотек и программных компонентов, если условия их лицензирования позволяют применение в рамках проекта.

#### 3.5.8 Сроки

Разработка системы выполняется в рамках учебного проекта по дисциплине «Жизненный цикл разработки программного обеспечения».

В первую версию продукта должны войти регистрация и авторизация пользователей, управление экзаменами и темами, планирование повторений, сохранение результатов и отображение статистики подготовки.

Сроки реализации определяются календарным планом учебного проекта.

#### 3.5.9 Доказательство концепции

Для подтверждения реализуемости основных функций системы необходимо проверить возможность создания экзаменов и тем, сохранения результатов подготовки и автоматического расчёта дат повторений.

Ключевым элементом проверки является работа алгоритма интервального повторения. Проверка должна подтвердить корректность изменения интервалов после сохранения результатов подготовки.

Результаты проверки используются для подтверждения возможности реализации основных функциональных требований первой версии продукта.

#### 3.5.10 Управление изменениями

**ID:** REQ-CM-001

**Title:** Управление изменениями требований и исходного кода

**Statement:** Изменения требований и исходного кода системы должны фиксироваться в репозитории проекта с использованием системы контроля версий.

**Rationale:** Контроль изменений необходим для отслеживания истории разработки, проверки внесённых изменений и согласования результатов работы.

**Acceptance Criteria:**
- Исходный код и документация проекта хранятся в репозитории.
- Изменения фиксируются отдельными коммитами.
- Для значимых изменений может создаваться Pull Request.
- Pull Request должен содержать описание внесённых изменений.
- Перед объединением изменений в основную ветку выполняется проверка изменений.
- Изменения спецификации требований фиксируются в истории изменений документа.

**Verification Method:** Inspection

**More Information:** Репозиторий проекта: https://github.com/graphffy/SDLC.

В каталоге `img` размещаются изображения пользовательского интерфейса системы. В каталоге `sysml` размещаются диаграммы, описывающие структуру и взаимодействие компонентов продукта.

### Приложение Б. Основные функциональные сценарии

Основные сценарии использования системы:

1. Пользователь регистрируется в системе и выполняет вход в свою учётную запись.
2. Пользователь создаёт экзамен и добавляет к нему учебные темы.
3. Система формирует расписание повторений для добавленных тем.
4. Пользователь просматривает расписание и выполняет запланированные повторения.
5. Пользователь сохраняет результат подготовки по выбранной теме.
6. Система обновляет расписание повторений и показатели подготовки.
7. Пользователь просматривает слабые темы, процент готовности и статистику подготовки.
